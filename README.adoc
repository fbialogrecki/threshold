= Threshold
:toc:
:toclevels: 2

Threshold is an open-source social and event-discovery platform for local music scenes. It combines chronological community feeds, public profiles and pages, groups, events, media, notifications, and organizer-managed guestlists without algorithmic ranking or third-party tracking.

NOTE: Active MVP development. APIs, data models, and deployment procedures may change before the first stable release.

== Product direction

Threshold focuses on direct community relationships:

* chronological content from followed people, pages, groups, and events;
* public artist, venue, collective, promoter, and user profiles;
* groups, posts, comments, votes, reactions, and moderation;
* public event discovery, follows, boosts, lineups, and updates;
* private organizer/DJ-managed guestlists with quotas and QR check-in;
* privacy-first operation without third-party trackers.

The MVP excludes ticketing, payments, direct messages, creator monetization, mobile applications, and algorithmic feeds.

== Architecture

[cols="1,3",options="header"]
|===
|Component |Responsibility
|`apps/web` |Next.js App Router frontend and browser-facing BFF
|`services/users` |Product authentication, sessions, profiles, pages, follows, and canonical blocks
|`services/social` |Groups, posts, comments, reactions, chronological feed, and moderation
|`services/events` |Event CRUD, public event reads, follows, boosts, guestlists, and check-in
|`services/media` |Image validation, metadata, derivatives, and S3-compatible storage
|`services/auth-gateway` |Authentik-backed SSO edge for internal and administrative surfaces
|`libs/py` |Shared Python helpers
|`libs/proto` |Internal Protobuf contracts
|===

Runtime stack:

* Web: Next.js, React, TypeScript, Tailwind CSS, Bun
* Services: Python 3.13, FastAPI, SQLAlchemy, Alembic
* Data: PostgreSQL via CloudNativePG; S3-compatible object storage
* Messaging: NATS Core
* Secrets: OpenBao and External Secrets Operator
* Delivery: Woodpecker CI, Harbor, Argo CD, Kustomize, Kubernetes
* Observability: OpenTelemetry and the Grafana LGTM stack

== Getting started

[source,bash]
----
git clone https://github.com/fbialogrecki/threshold.git
cd threshold
uv sync --frozen
(cd apps/web && bun install --frozen-lockfile)
cp apps/web/.env.example apps/web/.env.local
go-task web:dev
----

The development server uses http://localhost:3000[]. The link:apps/web/.env.example[example environment file] contains development placeholders only. Never commit `.env.local`, credentials, tokens, kubeconfigs, or rendered Kubernetes secrets.

`go-task web:dev` and `go-task dev` start only the web UI/BFF, not backend services or infrastructure. Backend-dependent features require separately configured services, PostgreSQL, NATS, and object storage. The example URLs are loopback placeholders, not provisioned dependencies. An isolated full-product startup workflow is not yet verified; private deployment access is not a prerequisite for editing the UI or running source checks.

For a production-mode web build and loopback startup (illustrative defaults):

[source,bash]
----
cd apps/web
AUTH_COOKIE_SECURE=true bun run build
AUTH_COOKIE_SECURE=true HOSTNAME=127.0.0.1 PORT=3000 bun run start
----

`build` prepares the Next.js standalone server and copies its static/public assets; `start` runs `.next/standalone/server.js`. The matching build/start path has been locally verified, including asset delivery. The retired `bun-dist/server.js` is not a fallback. Secure cookies require HTTPS for real browser authentication; this loopback example is a web startup check, not backend login or full-product verification. The remaining dependency/security remediation (W03) and isolated full-product/backend startup verification (W07) are not established by this web check.

== Quality gates

[source,bash]
----
uv sync --frozen
uv run --frozen ruff check .
uv run --frozen mypy .
uv run --frozen pytest -q
----

Web checks, from the source repository root with Bun 1.4.0 on `PATH`:

[source,bash]
----
(cd apps/web && bun install --frozen-lockfile && bun test ./src ./tooling && ./node_modules/.bin/tsc --noEmit && ./node_modules/.bin/eslint && AUTH_COOKIE_SECURE=true bun run build)
go-task repo:secret-scan
go-task proto:lint
go-task proto:generate
----

These are source checks, not deployment or full-product verification. `go-task install` uses frozen Python and web installs; `AUTH_COOKIE_SECURE=true go-task check` runs the required lint, type, unit-test, and build commands without conditional success skips. Missing expected projects, configurations, test roots/files, or local checking tools fail the affected targets. Web unit tests explicitly select `src` and `tooling`, not future end-to-end suites. Run `python3 -m unittest ci.tests.test_task_contract -v` with go-task installed for executable Taskfile contract tests; their isolated fake tools verify invocation and failure behavior, not application correctness. The repository secret scan is a lightweight check, not a substitute for the full-history security checks in link:.github/workflows/ci.yml[CI]. Protobuf generation changes generated files; review its diff.

== Contributing

Focused issues and pull requests are welcome. Keep changes inside the stated MVP scope, add tests for changed behavior, run the quality gates, and never commit secrets or private operational data.

Untrusted pull-request jobs run without release, registry-push, signing, Kubernetes, or GitOps credentials.

The intended release contract is: validated public source SHA -> immutable OCI image digest(s) -> reviewed digest-only pull request to the separate public GitOps repository's `main` -> deployment verification. Product source is never synchronized through a private mirror. Untrusted jobs must never receive promotion credentials; release credentials and private environment values belong only in trusted operator configuration.

The checked-in link:.woodpecker/release.yml[release workflow] currently declares both `push` and `manual` events on `main`. A verified manual-release path and its end-to-end trust checks are not yet established; the intended sequence above is not a claim that release is operationally proven.
